# ========================== phm_super8_config.yaml 参数说明 ==========================
# 该配置文件用于控制 PHM 2009 spur8 数据集在“不平衡小样本域泛化”设定下的预处理过程。
# 它决定了：
# 1) 原始数据从哪里读取；
# 2) 哪些类别参与预处理；
# 3) 哪个类别被视为正常类；
# 4) 哪些工况作为源域、目标域、验证域；
# 5) 每个域中正常类和故障类各抽取多少样本；
# 6) 滑窗参数、频域特征参数、时频图参数；
# 7) 当常规滑窗不足时，如何在同一文件内部进行错位重叠补样；
# 8) 预处理结果输出到哪里，以及保存时采用什么任务命名。
#
# 整个配置文件通常分为以下几个部分：
# - seed
# - dataset
# - split
# - sampling
# - feature
# - output
#
# ------------------------------------------------------------------------------
# seed
# ------------------------------------------------------------------------------
# seed: 2026
#
# 含义：
#   随机种子，用于控制整个预处理流程中的随机行为，使得结果可复现。
#
# 主要影响：
#   1) 从候选滑窗中随机抽取哪些窗口；
#   2) 当两个文件之间需要补样时，具体抽到哪些起点；
#   3) 当候选窗口很多但只需要部分样本时，最终的抽样选择顺序。
#
# 建议：
#   - 如果你希望多次运行得到完全一致的数据划分结果，应固定该值不变。
#   - 如果你想做多次独立重复实验，可以改不同 seed，生成多套不同的抽样结果。
#
# ------------------------------------------------------------------------------
# dataset
# ------------------------------------------------------------------------------
# dataset:
#   root_dir: "/path/to/PHM2009_spur8"
#   class_folders:
#     - "spur 1"
#     - "spur 2"
#     - "spur 3"
#     - "spur 4"
#     - "spur 5"
#     - "spur 6"
#     - "spur 7"
#     - "spur 8"
#   normal_class_folder: "spur 1"
#
# dataset 是“数据源定义区”，用于告诉程序：
#   原始数据集在哪、有哪些类别、哪一个类别是正常类。
#
# ------------------
# dataset.root_dir
# ------------------
# 含义：
#   PHM 2009 spur8 原始数据集的根目录路径。
#
# 作用：
#   代码会在该目录下寻找每一个类别文件夹，例如：
#     root_dir/
#       spur 1/
#       spur 2/
#       ...
#       spur 8/
#
# 要求：
#   - 该路径必须真实存在；
#   - 目录下必须包含 class_folders 中列出的所有子文件夹；
#   - 每个类别文件夹中应包含对应的 txt 文件。
#
# 注意：
#   - Windows 路径建议使用双反斜杠 \\ 或者正斜杠 /；
#   - 若路径错了，程序通常会报“类别文件夹不存在”或“找不到文件”的错误。
#
# ----------------------
# dataset.class_folders
# ----------------------
# 含义：
#   一个列表，表示要参与本次预处理的所有类别文件夹名称。
#
# 作用：
#   1) 决定程序会去 root_dir 下读取哪些类别目录；
#   2) 决定最终标签 y 的类别顺序；
#   3) 决定 label_map 的映射关系。
#
# 例如：
#   class_folders:
#     - "spur 1"
#     - "spur 2"
#     - ...
#     - "spur 8"
#
# 则最终通常会映射为：
#   "spur 1" -> 0
#   "spur 2" -> 1
#   ...
#   "spur 8" -> 7
#
# 要求：
#   - 名称必须与真实文件夹名完全一致；
#   - 顺序不要随意改变，除非你明确想改变标签编号。
#
# 重要说明：
#   class_folders 的顺序就是最终类别标签的顺序。
#   因此，如果你后续要写论文、画混淆矩阵或对接训练代码，必须知道这个顺序。
#
# ----------------------------
# dataset.normal_class_folder
# ----------------------------
# 含义：
#   指定哪一个类别文件夹被视为“正常类”。
#
# 作用：
#   在不平衡小样本设定中，正常类和故障类通常采用不同的抽样数量。
#   程序会根据该参数判断：
#   - 哪个类使用 normal_per_domain 抽样数；
#   - 哪些类使用 fault_per_class_per_domain 抽样数。
#
# 例如：
#   normal_class_folder: "spur 1"
#
# 则表示：
#   - "spur 1" 被当成正常类；
#   - 其余 "spur 2"~"spur 8" 被当成故障类。
#
# 非常重要：
#   这个参数必须与你的数据集真实标签一致。
#   如果正常类设错，那么虽然程序可以正常运行，但整个实验语义会出错。
#
# ------------------------------------------------------------------------------
# split
# ------------------------------------------------------------------------------
# split:
#   source_conditions:
#     - "30hz_High"
#     - "35hz_High"
#     - "40hz_High"
#   target_condition: "45hz_High"
#   use_val: false
#   val_condition: "40hz_High"
#
# split 是“任务划分区”，用于定义：
#   哪些工况作为源域训练、哪个工况作为目标域测试、是否划分验证域。
#
# -------------------------
# split.source_conditions
# -------------------------
# 含义：
#   一个列表，表示本次任务中哪些工况作为源域。
#
# 作用：
#   这些工况会被用于生成训练集；
#   若 use_val=true，其中一个工况还会被拿出来作为验证集。
#
# 例如：
#   source_conditions:
#     - "30hz_High"
#     - "35hz_High"
#     - "40hz_High"
#
# 表示当前任务以这 3 个工况作为源域。
#
# 要求：
#   - 列表中的工况必须真实存在于数据文件名中；
#   - 不能与 target_condition 重复；
#   - 若 use_val=true，则 val_condition 必须来自该列表。
#
# 实验意义：
#   这决定了“哪些域参与训练”，是域泛化任务定义的核心部分。
#
# -------------------------
# split.target_condition
# -------------------------
# 含义：
#   表示本次任务中哪个工况作为目标域。
#
# 作用：
#   程序会用该工况生成测试集；
#   该工况不能与 source_conditions 重复。
#
# 例如：
#   target_condition: "45hz_High"
#
# 表示 45hz_High 为未见目标域，用于最终测试。
#
# 实验意义：
#   这是域泛化评测中的“未见域”。
#
# ----------------
# split.use_val
# ----------------
# 含义：
#   一个布尔值，用于控制是否单独划分验证集。
#
# 取值：
#   - false：不划分验证集，只生成 train/test
#   - true ：划分验证集，生成 train/val/test
#
# 当为 false 时：
#   所有 source_conditions 一起用于训练，target_condition 用于测试。
#
# 当为 true 时：
#   source_conditions 中会有一个工况被单独拿出来作为验证域，
#   剩余源域用于训练，target_condition 用于测试。
#
# 建议：
#   - 如果你目前是先模仿原论文设定，建议先设为 false；
#   - 如果你后续要做调参、早停、模型选择，再考虑设为 true。
#
# ----------------------
# split.val_condition
# ----------------------
# 含义：
#   当 use_val=true 时，指定哪一个源域工况被拿出来作为验证域。
#
# 作用：
#   程序会将该工况从 source_conditions 中移出，单独生成 val.h5。
#
# 要求：
#   - 必须来自 source_conditions；
#   - 当 use_val=false 时，该参数通常不会实际生效。
#
# 例如：
#   source_conditions = ["30hz_High", "35hz_High", "40hz_High"]
#   val_condition = "40hz_High"
#
# 则表示：
#   - train 用 30hz_High 和 35hz_High
#   - val   用 40hz_High
#   - test  用 target_condition
#
# ------------------------------------------------------------------------------
# sampling
# ------------------------------------------------------------------------------
# sampling:
#   source:
#     normal_per_domain: 200
#     fault_per_class_per_domain: 1
#   target:
#     normal_per_domain: 200
#     fault_per_class_per_domain: 20
#   val:
#     normal_per_domain: 200
#     fault_per_class_per_domain: 20
#
# sampling 是“样本数量控制区”，用于定义每个 split 中每个域应该抽多少样本。
# 你的设定是“不平衡小样本域泛化”，所以正常类和故障类使用不同抽样数。
#
# -----------------
# sampling.source
# -----------------
# 含义：
#   控制训练域（源域）中的抽样数量。
#
# ------------------------------
# sampling.source.normal_per_domain
# ------------------------------
# 含义：
#   在每一个源域中，正常类要抽取多少个样本。
#
# 例如：
#   normal_per_domain: 200
#
# 表示：
#   每个 source condition 中，正常类都抽 200 个样本。
#
# 如果有 3 个源域，则训练集中正常类总数通常是：
#   200 × 3 = 600
#
# --------------------------------------------
# sampling.source.fault_per_class_per_domain
# --------------------------------------------
# 含义：
#   在每一个源域中，每一个故障类别要抽取多少个样本。
#
# 例如：
#   fault_per_class_per_domain: 1
#
# 表示：
#   每个源域中，每个故障类只抽 1 个样本。
#
# 若总共有 7 个故障类、3 个源域，则训练集中所有故障样本总数通常为：
#   7 × 1 × 3 = 21
#
# 实验意义：
#   这个参数决定了训练时的 few-shot 程度。
#   例如：
#   - 1 表示极端 1-shot
#   - 5 表示 5-shot
#   - 10 表示 10-shot
#
# -----------------
# sampling.target
# -----------------
# 含义：
#   控制目标域（测试域）中的抽样数量。
#
# 一般来说，测试集不会像训练集那样极端 few-shot，而是给每类更多样本用于稳定评估。
#
# ------------------------------
# sampling.target.normal_per_domain
# ------------------------------
# 含义：
#   在目标域中，正常类抽多少个样本。
#
# 例如：
#   normal_per_domain: 200
#
# 表示测试域中正常类抽 200 个样本。
#
# --------------------------------------------
# sampling.target.fault_per_class_per_domain
# --------------------------------------------
# 含义：
#   在目标域中，每个故障类抽多少个样本。
#
# 例如：
#   fault_per_class_per_domain: 20
#
# 表示测试域中每个故障类抽 20 个样本。
#
# 实验意义：
#   这个参数决定测试集评估时每个故障类的样本量。
#   数量更大时，测试指标更稳定、更能反映泛化能力。
#
# 例如对于 8 类任务：
#   1 个正常类 + 7 个故障类
#   测试总样本数一般为：
#   200 + 7×20 = 340
#
# -------------
# sampling.val
# -------------
# 含义：
#   控制验证域中的抽样数量，仅在 use_val=true 时实际使用。
#
# 一般建议：
#   验证集不要沿用训练集那种极端 few-shot，而应相对充足一些，
#   这样选模型、做早停会更稳定。
#
# ------------------------------
# sampling.val.normal_per_domain
# ------------------------------
# 含义：
#   验证域中正常类抽多少个样本。
#
# --------------------------------------------
# sampling.val.fault_per_class_per_domain
# --------------------------------------------
# 含义：
#   验证域中每个故障类抽多少个样本。
#
# 常见建议：
#   可与 target 保持一致，例如：
#   - 正常类 200
#   - 每个故障类 20
#
# ------------------------------------------------------------------------------
# feature
# ------------------------------------------------------------------------------
# feature:
#   win_len: 2048
#   stride: 1024
#   zscore_per_window: true
#   fft_mode: "power"
#   tf_image_size: [128, 128]
#   x_tf_dtype: "float16"
#   overlap_sampling:
#     enabled: true
#     offsets: [512, 256, 768]
#   stft:
#     nperseg: 256
#     noverlap: 128
#     nfft: 256
#
# feature 是“特征构造区”，用于控制：
#   1) 滑窗怎么切；
#   2) 频域特征怎么做；
#   3) 时频图怎么做；
#   4) 常规滑窗不够时，如何进行错位重叠补样。
#
# ----------------
# feature.win_len
# ----------------
# 含义：
#   每个样本窗口的长度，即从原始一维振动信号中每次截取多少个点作为一个窗样本。
#
# 例如：
#   win_len: 2048
#
# 表示：
#   每个样本是长度为 2048 的一维时域片段。
#
# 影响：
#   - 决定每个样本包含的时域信息多少；
#   - 决定频域特征长度；
#   - 决定时频图输入内容。
#
# 例如：
#   当 win_len = 2048 时，rFFT 的输出长度通常是：
#   2048/2 + 1 = 1025
#
# ----------------
# feature.stride
# ----------------
# 含义：
#   常规滑窗的步长，即相邻两个窗口起点之间相隔多少点。
#
# 例如：
#   stride: 1024
#
# 表示：
#   常规滑窗起点为：
#   0, 1024, 2048, 3072, ...
#
# 影响：
#   - stride 越小，可切出的窗口越多；
#   - stride 越小，相邻样本重叠越大；
#   - stride 越大，样本间冗余越小，但样本数也更少。
#
# ---------------------------
# feature.zscore_per_window
# ---------------------------
# 含义：
#   是否对每个滑窗样本单独做 z-score 标准化。
#
# 取值：
#   - true  ：每个窗口单独标准化
#   - false ：不做该标准化
#
# z-score 的含义：
#   对一个窗口内的数值减去均值，再除以标准差，使其均值约为 0，方差约为 1。
#
# 作用：
#   - 减小不同窗口间幅值尺度差异；
#   - 让频域和时频图特征更稳定；
#   - 常用于振动信号建模。
#
# ------------------
# feature.fft_mode
# ------------------
# 含义：
#   控制频域特征使用 rFFT 后的哪一种形式。
#
# 取值：
#   - "power"     ：使用功率谱，即 |FFT|^2
#   - "magnitude" ：使用幅值谱，即 |FFT|
#
# 当前流程：
#   先对窗口做 rFFT，再取 power 或 magnitude，最后做 log1p 压缩。
#
# 建议：
#   多数情况下使用 "power" 更常见，因为能量表达更强。
#
# -----------------------
# feature.tf_image_size
# -----------------------
# 含义：
#   最终输出的时频图尺寸 [H, W]。
#
# 例如：
#   tf_image_size: [128, 128]
#
# 表示：
#   每个窗样本生成的 STFT 功率图会被 resize 到 128×128。
#
# 最终 x_tf 的 shape 就是：
#   [N, 1, 128, 128]
#
# 作用：
#   统一所有样本时频图尺寸，方便后续 CNN 或多模态模型输入。
#
# --------------------
# feature.x_tf_dtype
# --------------------
# 含义：
#   控制时频图 x_tf 在 h5 中保存时的数据类型。
#
# 常见取值：
#   - "float16"
#   - "float32"
#
# 区别：
#   float16：
#     - 占用空间更小
#     - 保存更省磁盘
#     - 适合大规模预处理
#   float32：
#     - 精度更高
#     - 更稳妥
#     - 占用空间更大
#
# 建议：
#   如果数据量大且希望节省空间，可用 float16；
#   如果特别重视数值精度，可用 float32。
#
# ---------------------------
# feature.overlap_sampling
# ---------------------------
# 含义：
#   控制当常规滑窗候选样本不足时，是否在同一原始文件内部进行“错位重叠采样”补样。
#
# 这个模块是为了解决以下问题：
#   某个类-某个工况下，如果对应两个原始 txt 文件按常规滑窗切分后，
#   总候选窗口数仍然不足以满足设定抽样数，则不能去其他工况或其他域借数据，
#   只能在这两个文件内部继续构造新的、与原滑窗不完全重合的窗口。
#
# -----------------------------------
# feature.overlap_sampling.enabled
# -----------------------------------
# 含义：
#   是否启用错位重叠补样。
#
# 取值：
#   - true  ：启用
#   - false ：不启用
#
# 当为 true 时：
#   若 base 滑窗不足，程序会在同一文件中使用 offset 构造新的 overlap 候选窗。
#
# 当为 false 时：
#   若 base 滑窗不足，则不会做额外补样，更容易报样本不足错误。
#
# -----------------------------------
# feature.overlap_sampling.offsets
# -----------------------------------
# 含义：
#   指定错位重叠采样时使用的偏移量列表。
#
# 例如：
#   offsets: [512, 256, 768]
#
# 若 stride=1024，则这些 offset 会产生额外起点序列，例如：
#   offset=512 -> 512, 1536, 2560, ...
#   offset=256 -> 256, 1280, 2304, ...
#   offset=768 -> 768, 1792, 2816, ...
#
# 作用：
#   这些起点与常规滑窗起点（如 0, 1024, 2048, ...）不同，
#   因此可以在同一原始文件内部形成新的、非完全重复的窗口样本。
#
# 注意：
#   - offset 必须大于 0 且小于 stride；
#   - offset 越多，可构造的 overlap 候选窗通常越多；
#   - 但过多 offset 也可能导致样本之间相关性变强。
#
# -------------
# feature.stft
# -------------
# 含义：
#   控制时频图（STFT）的计算方式。
#
# --------------------
# feature.stft.nperseg
# --------------------
# 含义：
#   STFT 每个短时窗的长度。
#
# 作用：
#   决定 STFT 在时间和频率上的局部分析粒度。
#
# 一般规律：
#   - nperseg 大：频率分辨率更高，时间分辨率相对更低
#   - nperseg 小：时间分辨率更高，频率分辨率相对更低
#
# ----------------------
# feature.stft.noverlap
# ----------------------
# 含义：
#   STFT 相邻短时窗之间的重叠长度。
#
# 作用：
#   控制 STFT 计算时的时间平滑程度。
#
# 一般规律：
#   - noverlap 越大，时间帧之间重叠越多，图更平滑；
#   - noverlap 越小，计算更稀疏。
#
# 要求：
#   通常应满足：
#     noverlap < nperseg
#
# ----------------
# feature.stft.nfft
# ----------------
# 含义：
#   STFT 中每帧 FFT 的长度。
#
# 作用：
#   决定 STFT 频率轴的离散点数。
#
# 一般规律：
#   - nfft 越大，频率轴采样越细；
#   - 通常 nfft >= nperseg。
#
# 当前流程：
#   时域窗 -> STFT -> 功率谱 -> log1p -> resize -> x_tf
#
# ------------------------------------------------------------------------------
# output
# ------------------------------------------------------------------------------
# output:
#   output_dir: "/path/to/output_h5"
#   task_name: "PHM_spur8_T1"
#
# output 是“输出控制区”，用于指定生成的 h5 和 trace 文件保存到哪里，以及使用什么命名。
#
# -------------------
# output.output_dir
# -------------------
# 含义：
#   预处理结果保存目录。
#
# 输出通常包括：
#   - train.h5 / val.h5 / test.h5
#   - train_trace.json / val_trace.json / test_trace.json
#
# 例如：
#   output_dir: "./PHM_spur"
#
# 则最终可能生成：
#   ./PHM_spur/PHM_spur8_T1_train.h5
#   ./PHM_spur/PHM_spur8_T1_test.h5

# ----------------
# output.task_name
# ----------------
# 含义：
#   当前任务的名称前缀，用于构造输出文件名。
#
# 例如：
#   task_name: "PHM_spur8_T1"
#
# 则输出文件通常会命名为：
#   PHM_spur8_T1_train.h5
#   PHM_spur8_T1_test.h5
#   PHM_spur8_T1_train_trace.json
#   PHM_spur8_T1_test_trace.json
#
# 作用：
#   用于区分不同实验任务。
#
# 建议：
#   任务名最好能直接体现：
#   - 数据集名称
#   - 类别版本
#   - 任务编号
#   例如：
#   - PHM_spur8_T1
#   - PHM_spur8_T2
#   - PHM_spur8_200to1_T1
#
# ------------------------------------------------------------------------------
# 一整套配置如何共同起作用
# ------------------------------------------------------------------------------
# 以一个典型设定为例：
#
# 1) dataset 决定读哪些类别目录，以及哪个类别是正常类；
# 2) split 决定哪些工况是源域、哪个工况是目标域；
# 3) sampling 决定每个域里正常类和故障类分别抽多少个样本；
# 4) feature 决定每个样本怎么从原始信号切窗、怎么生成频域和时频图；
# 5) 当普通滑窗不够时，feature.overlap_sampling 决定是否在同一文件内做错位补样；
# 6) output 决定最终 h5 和 trace.json 保存在哪里，以及采用什么文件名。
#
# ------------------------------------------------------------------------------
# 一句话总结
# ------------------------------------------------------------------------------
# 这个配置文件本质上就是“PHM spur8 不平衡小样本域泛化预处理任务说明书”。
# 它完整规定了：
#   数据来源、类别定义、正常类定义、域划分方式、每类每域的抽样数量、
#   频域与时频特征生成方式、样本不足时的补样策略，以及最终输出命名方式。
# 只要配置文件固定，预处理脚本就能以可复现的方式生成对应的 h5 数据集。
# ==============================================================================
